# STATUS – Travel Agent (BIU DS23, צוות 8) – 21.10.2026

**English summary.**
- **What we build:** a zero-cost travel-planning agent (CrewAI Flows) for Chicago and New York, on cached 2022 data.
- **Systems compared:** rules (A, basic and strong variants), single agent (B), multi-agent with 3 agents (C), plus a new **hybrid H** (one LLM parse call + strong rules).
- **Central metric:** `valid_plan_rate` with a Wilson 95% CI, also on the true-conflict subset.
- **Structured segment (v2):** 40 eval + 8 dev cases, with an oracle-verified true conflict. Strong rules reach the ceiling there (1.00 on valid plans, conflicts and quality). So structured cases cannot show an LLM or multi-agent advantage.
- **Free-text segment (v3, new):** 20 eval + 4 dev cases, text only. Each case has hidden gold fields and 2–3 deterministic key requirements (met / flagged / ignored), plus an optional LLM judge with a rubric.
- **System A on v3** (keyword parser + strong rules):
  - `valid_plan_rate` (gold) = 9/20 = 0.45 [0.26, 0.66]: direct 0.70, indirect 0.20.
  - Key requirements: 48 met / 0 flagged / 8 ignored of 56. Direct 28/0/0, indirect 20/0/8.
- **Open:** B, C and H have not run (they need a free LLM: Ollama or a free Groq/Gemini key); PR #1 and PR #2 await Galit's approval; NYC food gaps; CHARTER update.

## 5. מערכת A – שני baselines (על v2 eval)
- **`rules_basic` (A0):** בוחר את החבילה הזולה, ממלא מקומות בצורה גרידית, ומציין בקצרה את מה שוויתר עליו.
- **`rules` (A-strong, ברירת המחדל):**
  - בחירה מחזית פארטו (עם משקלי עדיפות);
  - טקסט ויתורים מתבנית;
  - רלוונטיות ובולטות (Wikivoyage + Wikidata);
  - `TYPE_HOURS`;
  - בלי שתי פעילויות צמודות מאותה קטגוריה;
  - מילוי ימים;
  - בימי גשם, רק פעילויות בפנים.
- **תוצאות A-strong:** ‏valid 36/36, התנגשויות 24/24, וכל בדיקות האיכות 1.00. האיכות של A0 נמוכה בבירור (ראו `eval/reports/rules-basic-vs-strong-v2-*`).
- **ממצא:** A-strong מגיע לתקרה על בקשות מובנות. לכן בקשות מובנות לא יכולות להראות יתרון ל-LLM או למולטי-אג'נט.

## 6. החלטות חדשות (21.10.2026)
- **(א) מקטע טקסט חופשי:** כ-20 בקשות eval ועוד 4 dev, בשיקגו ובניו יורק. לכל בקשה יש `request_text` בלבד (באנגלית טבעית) ו-`phrasing_type` ‏direct או indirect. הבקשות כוללות שלילה, אילוצים עקיפים, עדיפויות ומתח פנימי.
- **(ב) מערכת רביעית – היברידית (H):** קריאת LLM אחת לפענוח, ואחריה הכללים החזקים. גרסת הכללים עם מפענח מילות מפתח וביטויים רגולריים נשארת כמערכת A על טקסט חופשי.
- **(ג) שדות כלליים בסכמה:**
  - `daily_blocked_windows`;
  - `max_walk_minutes`;
  - `day_start` / `day_end`;
  - `accessibility`;
  - `no_early_flight_before`;
  - `priority_weights`;
  - `unparsed_requirements`.

  השדות אופציונליים ותואמים לאחור, והכללים החזקים מכבדים אותם.
- **(ד) הערכה בשתי שכבות לטקסט חופשי:**
  1. **בדיקות דטרמיניסטיות:** 2–3 דרישות מפתח מוסתרות לכל בקשה. הציון הוא שיעור הדרישות שמולאו. "סומן כלא טופל" (flagged) נספר בנפרד מ"התעלמות שקטה" (ignored).
  2. **LLM-as-judge:**
     - **רובריקה:** קצרה, ציון 1–5 לכל קריטריון עם הצדקה קצרה.
     - **הרצה:** `temperature=0`, תוכנית אחת בכל קריאה, ומודל שופט שונה ממודל הסוכנים.
     - **קלט:** סיכום תמציתי של פחות מכ-1k tokens, ולא התוצאה הגולמית של כ-170KB.
     - **תקציב:** כ-80 שיפוטים, כ-150k tokens, בתוך מכסות חינמיות.
     - **כיול:** הצוות ידרג כ-20 תוכניות בדירוג עיוור.
- **(ה) הוגנות:**
  - **מודל:** H, ‏B ו-C משתמשים באותו מודל.
  - **רישום:** קריאות LLM, tokens וזמן נרשמים.
  - **טבלה סופית:** 4 מערכות, בנפרד למקטע המובנה ולמקטע הטקסט החופשי.
- **(ו) היקף:** היקף קטן שמתאים לבנייה של שבועיים.

## 7. מה נבנה ב-v3 (ענף `feat/eval-v2-conflicts`, ‏PR #2)
- **מודל ובחירה:**
  - הרחבת `TripRequest` ו-`FreeTextRequest`;
  - `no_early_flight_before` כמסנן קשיח בצעד המועמדים;
  - הכללים החזקים מכבדים חלונות חסומים, הליכה מרבית ומשקלי עדיפות, ומסמנים "not handled" לנגישות ולדרישות שלא פוענחו.
- **מפענחים:**
  - `parsing/parse_rules.py`: מילות מפתח, כוונן על dev בלבד, וקפא לפני ה-eval;
  - `parsing/parse_llm.py`: קריאה אחת, אימות pydantic, ותיקון אחד לכל היותר.
- **מערכות:**
  - `--system hybrid`;
  - B ו-C מקבלים גם בקשה בטקסט חופשי בלבד, ומפענחים אותה עם אותה קריאת LLM;
  - בלי LLM זמין, הסטטוס הוא `TECHNICAL_ERROR`.
- **הערכה:**
  - `eval/keyreq.py` (14 checkers);
  - `eval/score_v3.py`;
  - `eval/judge.py` (נבדק עם LLM מזויף ולא הורץ מול LLM אמיתי);
  - `run_eval --cases v3`, שמעביר למערכת רק `id`, `request_text` ו-`as_of`, ובודק את התוכנית מול בקשת ה-gold.
- **בדיקות:** 96 טסטים ירוקים, מהם 20 חדשים.
